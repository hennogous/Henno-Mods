# Corrections and evidence cautions

This page records conclusions that must be read differently from older wording. The investigation reports remain dated evidence; the handbook states the reconciled position. A newer document supersedes an older assertion only where it supplies a correction or different verified scope. A later date alone does not invalidate an earlier experiment.

## Working rules for future corrections

- Preserve the original report and identify the exact assertion being replaced or narrowed.
- Keep game-binary identity, source/profile version, caller and context attached to native conclusions. A recovered symbol or old Linux offset is a lead until verified for the current Windows target.
- Label evidence type and current standing separately. Static evidence can settle an algorithm while leaving its gameplay effect unmeasured; a runtime observation can be strong but narrowly scoped.
- Trace dependencies. If a function mapping changes, recheck all conclusions that relied on it, including diagrams and implementation recommendations.
- Keep failed controls and missing observations visible. Repairing a reporter offline must not invent missing execution, replay economic actions or relabel a failed probe as success.
- Separate configured source, installed package and archived executed text. New source fixes do not retroactively describe an older game's behaviour.

These rules are already supported by the [progress review](../../../integrations/csc-ai-progress-and-learnings-20261101.md) and the [current-build future-economy evidence](../../../research/mods/csc-future-economy-forecast-20261103.md). **[AI-H011]**
