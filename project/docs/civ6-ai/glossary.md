# Terms and evidence levels

## Read evidence at the level it establishes

| Level | What it establishes | What remains to be shown |
|---|---|---|
| Definition loaded | SQL/XML or configuration exists in the tested package | The relevant AI consumer reads it |
| Static consumer traced | A code path can consume the input in a specific context | The path executes for the relevant candidate |
| Runtime value delivered | A value reaches a captured evaluator | It changes selection |
| Recommendation or proposal | An option appears in a list or request | A specific worker or city accepts it |
| Selection or contract | Work wins an identified decision or becomes a request | It wins production and remains executable |
| Physical completion | The district, building or improvement exists | Required supply and customer conditions operate |
| Operating chain | Defined supply and customer conditions are observed | Net benefit and strategic value justify investment |
| Empire benefit | Relevant incremental yields/effects and costs are measured | Generalisation to other maps, clocks and profiles |

## Current standing and evidence type

**Accepted** means the assertion is supported within its stated scope.
**Provisional** means the interpretation or generalisation remains unsettled.
**Superseded** preserves an earlier assertion so it cannot silently re-enter the
current model. A correction can replace only part of an older claim.

**Static** means inspected native code. **Runtime** means observed execution or
game state. **Source** means shipped/mod data, scripts or a recorded design
decision. **Inference** means a conclusion drawn from those observations.
Multiple types may support one finding. None removes the need for a scope.

## Common terms

| Term | Meaning here |
|---|---|
| Candidate | A district/site, building or job being considered; not a promise to build it |
| Cached value | A previously calculated score reused by a later decision |
| Contract/request | Work represented in the AI's coordination machinery |
| Forecast | An input representing prospective benefit; not necessarily a complete future plan |
| Native | The game's ordinary engine decision route; separate from an external planner or forced order |
| Private yield | A custom yield channel used for guidance; its name does not guarantee AI-only or economically inert behaviour |
| Base / Specialty / Both | CSC material categories for the actual Quarter; Both means Base and Specialty potential/supply as defined by the particular measure |
| Full-supply context | A study's specific milestone requiring working supply, producer and matching customer conditions; not a complete profit calculation |
| Assistance | CSC's declared acquisition/foundation/planning intervention; distinguish its placements and costs from ordinary native placements |
| Basic / RH | Standalone CSC assistance and CSC compatibility with the reviewed RomanHoliday profile |
| Censored | An observation window ended before an investment had enough time to reach an outcome |
| Recovered symbol | A function name transferred or inferred during reverse engineering; verify its current binary address and behaviour |
| Q8 | Fixed-point representation with a scale of 256; raw integer scores require conversion before comparing with ordinary yield numbers |

Game binary identity, source version, active profile, world/save, speed, clock,
observer effects and missing intervals can all limit a conclusion. A saved-world
mechanism probe and a fresh-game comparison answer different questions.
