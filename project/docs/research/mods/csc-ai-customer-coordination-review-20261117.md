# Astra review: improving customer placement coherently

17 November2026, Problems1/2, **AI-C213**. Henno requested an independent
Astra review after the per-type placement counts and Perth trace. Astra reviewed
the shared facts/model/adapters, plan continuity, native SQL connectors and
current evidence. This is a proposed implementation sequence; no policy or game
was changed for the review.

## Recommended first slice: useful fresh comparisons under the existing budget

Keep SQL private adjacency+1 and the signed customer-site economic adapter.
Retain the16-world-forecast limit per player. Currently the loop prices a
reference and up to three alternatives before moving to the next city/type.
Instead:

1. Skip groups with only one usable site: there is no relative site difference.
2. First price a stable ordinary reference and one useful distinct challenger
   per city/type. Prefer an adjacent challenger if the reference is unlinked,
   or a strong ordinary competitor if it is linked; compare different linked
   options where those are the available alternatives.
3. Give a surviving attractive customer footprint an early turn when a real
   Quarter foundation matches its layout. A real foundation can create the
   opportunity even if no prior proposal was retained.
4. Rotate groups and plots fairly; spend remaining budget on further contenders.

This can cover eight useful pairs instead of four fully explored groups at the
same ceiling. Retain candidate identity and revalidate its legality/materials/
reference; do not publish an old signed score merely because it used to help.
An identity is a scheduling hint, not a native reservation or an extra bonus.

The current run logs2,787 visited of3,645 available group-publication windows
(76.5%), with858 unvisited. Late201–250 visits513/680. These are repeated work
windows rather than actual decision misses. SQL stays active, and an expired
packet does not by itself clear Civ's cached score. Trace comparison-time
coverage directly before interpreting this as lost choices.

## Concrete completion gate

Use a short matched saved-world replay with an existing Quarter, an owned legal
customer option and a competitive ordinary alternative. Keep SQL and economic
coefficients fixed. Compare old/new candidate scheduling through:

- fresh economic difference and the actual native post-aggregation comparison;
- near-tied site selection and subsequent foundation;
- a stronger ordinary site retaining its win;
- a lost/occupied/material-unsafe target dropping out;
- forecast count and late-game wall time against the1.97s average/3.86s maximum
  five-player run, using like-for-like worlds.

The first slice is candidate scheduling in existing Lua and packet mechanisms;
it does not require a new CE API. Preserve the native positive-cell safeguard,
building aggregation and normal type/production competition. If better coverage
does not improve the relevant comparison, use that result to choose the next fix.

## Subsequent slices, chosen by the observed bottleneck

**One shared connection record across both placement orders.** Maintain the
Quarter/material/customer footprint relationship through Quarter-first and
customer-first foundations. Revalidate soft geometry and remaining investments;
keep alternative sites and native competition. Build on the central gameplay-
derived model, rather than another Quarter-specific controller.

**Ordinary economic calibration.** When an offer lands and loses, inspect its
income, timing and opportunity costs alongside the winner. Perth's20 exact
positive losses belong here. Audit one+2 and one+3 quote, including staffed-tile
costs. It provides no reason to force a Quarter win or undo weak-site policy.

**Customer acquisition and future eligibility.** Count affordable, correctly
assignable, otherwise legal frontier opportunities before extending purchases.
Keep locked types/slots as future layout hints until actionable; future customers
still earn no invented current adjacency. Add the acquisition adapter where
missing land demonstrably blocks worthwhile connections.

**Services remain deferred.** Existing ordinary transactions can distinguish
customer sites. Missing producer buildings are a separate execution capability;
an inland Tailors has no legal Harbor neighbour. Preserve those distinctions.

## Outcome measures

Use the proportion of actual customer-type elections choosing a viable connection
when legal mapped and ordinary alternatives existed at decision time. Separately
record type selection versus other districts, candidate pricing/consumption,
within-type site choice, foundation and eventual economic/Service operation.
Measure customer-first preparation separately and deduplicate physical placements
through capture. Whole-map3/16 Hubs or0/13 Harbors describe resulting prevalence;
the opportunity-normalized measure identifies sensible choices left on the table.

Primary reviewer agrees with this sequence: close a small native decision loop,
then expand the shared connection capability based on the remaining bottleneck.
Avoid increasing all bids or rebuilding the architecture before that first test.
